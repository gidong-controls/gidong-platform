# PLC 개발 에이전트 사용자 흐름

최종 갱신: 2026-10-11. 제품 목표는 [PRD](../PRD.md), 실제 수정 순서는
[구현 계획](AGENT_PRODUCT_PLAN.md)이다. 아래는 목표 동작이며 아직 전체 구현 완료가 아니다.

## 기본 경험

사용자는 대화에서 작업을 맡긴다. Agent는 필요한 프로젝트·문서를 읽고 도구를 고르며,
실제 반환 결과로 다음 행동을 정한다. 같은 대화에 선택·실행·완료·실패가 이어서 표시된다.
프로젝트 선택과 필요한 연결 설정은 보조 UI이고, 미션·거래·증거 관리가 기본 화면이 아니다.

선정한 LD 경로는 실제 캡처 보관 → 작은 구조 지도·부분 조회 → 모델의 요소/포트 참조
편집 → native 실행 결과 → 모델의 후속 판단이다. 같은 관측의 상세 조회는 GUI를 다시
읽지 않는다. 실제 현재 LD가 필요한 시점은 모델이 선택한다.

| 사용자 요청 | 에이전트의 행동 | 사용자에게 보이는 결과 |
| --- | --- | --- |
| 이 프로그램을 설명해 줘 | 목록/LD/참조를 필요한 만큼 읽고 설명 | 실제 읽은 위치와 설명, 미확인 부분 |
| M30을 추가하는 안만 보여줘 | 현재 사용처·로직을 읽고 변경안을 작성 | 변경안과 영향. 적용은 하지 않음 |
| 이 작업 사본을 수정하고 저장해 줘 | 대상·사용처 확인 후 수정, 필요한 검사, 저장 | 바뀐 내용·저장 결과·남은 오류 |
| 동작도 시험해 줘 | 필요한 XG-SIM 입력/관찰 도구를 선택 | 기대값·관측값, STOP/입력 복원 결과 |
| 자기유지 LD를 새로 만들어 줘 | 필수 요구를 확인하고 설계·생성·검사·저장 | 생성 프로젝트/프로그램과 실제 결과 |
| 왜 실패했어? | 도구 오류와 현재 관측을 해석 | 실패 위치·원인/미확인 원인·다음 행동 |

설명 요청에는 편집 거래가 필요 없다. 시뮬레이션·독립 재열기는 요청하거나 결과 확인에
필요할 때 쓰는 도구다. 모든 저장을 종료→새 PID→재열기→SIM→Keep으로 강제하지 않는다.

## 권한과 실패 처리

지정 작업 사본에 대한 명확한 수정·저장 요청은 해당 범위의 권한이다. Host가 대화와
작업 대상에 그 범위를 기록하고 실행 단계에 전달한다. 도구마다 새 사용자 승인을 요구하지
않는다. 후보만 요청했거나 범위를 벗어나는 변경이 필요하면 실제 변경 전에 확인한다.
모델 출력이나 검색 문서가 사용자 권한을 임의로 넓힐 수는 없다.

기존 작업본의 native 수정·저장 대화는 Host·Agent·broker에 이미 연결돼 있다.
다음 구현은 신규 대상 준비·자료 조사와 일반 Web 제출을 이 경로에 연결하는 것이다.
현재 planning의 문자열 응답/Host plan-artifact 검증 불일치, Web 후속 요청의 scope reset,
mission 전용 재개와 실제 native 결과 요약 표시를 함께 정리한다. 정확한 producer/consumer와
완료 조건은 구현 계획 §4·§5에 있다. UI 버튼을 숨기거나 기존 루프를 새로 만드는 작업이 아니다.

대상 확인, 작업 사본 보호, 잘못된 대상에 쓰기 방지, 변경 여부 불명확 시 중복 실행 방지는
도구 내부에 유지한다. 실패한 작업 사본의 추가 변경을 제한하더라도 일반 대화·문서 분석·
다른 안전한 읽기는 진행할 수 있어야 한다. 사용자 파일·백업·기존 저널을 지워서 문제를
해결한 것처럼 만들지 않는다.

UAC가 필요한 정상 기동에서는 호출한다. 이미 승인된 실행 프로세스를 재사용하고,
실제 거부·취소가 확인됐을 때만 해당 승격을 멈춘다. UI/프로그램 열기 timeout을
권한 거부로 바꾸어 설명하지 않는다.

## 진행 표시와 사용자 개입

- 도구 선택은 모델의 실제 요청에서, 실행 시작은 dispatcher에서, 결과는 실제 반환에서 만든다.
- 카드에는 행동 이름, 대상, 상태, 경과 시간, 짧은 결과를 표시한다. 상세 결과는 접는다.
- heartbeat는 연결 생존 표시다. 실제 도구 실행이나 완료를 대신하지 않는다.
- 실패도 모델에 반환하여 수정된 인자·다른 읽기 도구·질문·중단 중 필요한 행동을 선택한다.
- 중단 요청을 받은 사실과 벤더 작업이 실제 멈춘 사실을 구분한다.
- 후속 지시로 같은 대화의 작업을 수정할 수 있어야 한다. 목표가 바뀔 때마다 새 대화를
  만들게 하거나 고정 미션 조건을 모두 닫도록 요구하지 않는다.
