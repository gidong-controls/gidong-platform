# ControlStudio 완성품 구현 계획

공통 구조·작업 분담·통합 규칙은 [루트 ARCHITECTURE](../../ARCHITECTURE.md), 제품 요구는 [PRD](../PRD.md), 현재 실행·적용 상태와 다음 작업은 [HANDOFF](../../HANDOFF.md)를 따른다.
## 구현 순서와 완료 조건

| 단계 | 담당 경계 | 구현할 동작 | 실제 완료 근거 |
| --- | --- | --- | --- |
| 1. 자료 조사·신규 대상 준비 | Platform → Agent → MCP/CLI | 자연어 요구와 설비 자료를 받아 실제 workspace/project/program을 생성하거나 선택하고 기존 native 대화로 연결 | 모델의 자료 조회·출처 사용, 실제 LD 작성·저장. 순수 상담은 불필요한 프로젝트 생성 없이 응답 |
| 2. 일반 웹 제작 | Web·Host·Agent | 대동인덱스 작성, 진행 표시, 후속 수정과 중단 재개를 같은 대화에서 수행 | 사용자 I/O·운전 조건에 맞는 작업본과 검사·저장 결과. 웹 표시와 실제 결과 일치 |
| 3. XG-SIM 수정 루프 | Agent·Host/broker·MCP/CLI | 시험 입력과 관측으로 모델이 문제를 판단하고 부분 수정한 뒤 저장·적용·재시험 | 실패 관측 → 모델 변경 → 수정본의 저장/적재 버전 → 재시험 결과가 연결됨 |
| 4. 후속 변경·재개·모델 설정 | Agent·Host·Web | 두 펌프 교번 운전의 수위·고장 전환, 가독성 개선, 후속 지시·중단·제공자 지연 처리 | 일반 도구로 회로 수정, 비대상 회로·심볼·설명 보존, 완료 입력의 중복 실행 없는 재개. 선택한 모델 설정 실제 사용 |
| 5. 제품 전달 | Launcher·4개 배포 패키지 | 단일 진입점의 설치·기동·업데이트 | 일반 웹 작업 수행 및 업데이트 후 설정·대화·프로젝트 보존 |

공통 실행 책임과 데이터 흐름은 [ARCHITECTURE](../../ARCHITECTURE.md)를 따른다.
