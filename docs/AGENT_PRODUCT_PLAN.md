# PLC Agent 구현 타당성과 완성품 구현 계획

갱신: 2026-10-05. 상태: **핵심 LD 실행 경로 미확보 — 타당성 판단 진행 중**.
요구사항은 [PRD](../PRD.md)를 따른다. 이 문서는 과거 감사/RB/SC/핸드오프를
순서대로 재수행하라는 지시와 기존 구현 재사용을 전제로 한 계획을 대체한다.
새 계획 문서를 계속 추가하지 않고 실행 결과를 여기에 갱신한다.

## 1. 먼저 해결할 문제

모델이 로직을 설계해도 실행기가 **실제 XG5000 LD에 접점·분기·코일을 생성하고
일부 구조를 바꿀 수 없다면** 제품은 성립하지 않는다. 현재 한-operand 변경 함수,
MNE/IL 변환, 전체 프로그램 붙여넣기는 이 요구의 대안이 아니다.

먼저 원본과 분리된 새 프로젝트에서 다음 핵심 동작을 수행한다.

1. LD에 직렬 접점·병렬 분기·코일을 작성한다.
2. 기존 분기의 일부 접점을 삽입/변경하여 대상 밖 구조를 보존한다.
3. XG5000 검사·저장을 수행하고 저장한 LD 구조를 다시 확인한다.

이 동작은 도구의 편집 능력을 확인하는 첫 단계일 뿐, 대표 장비나 자연어 Agent 완료가 아니다.
이 결과 없이 Agent scaffold·승인 계층·검사 기반 시설을 확대하지 않는다.

## 2. 지금 확인한 사실과 미확인

- 네 Git 저장소의 현재 정리 상태를 커밋했다:
  Platform `019ecee`, Agent `9fef68f`, MCP `7b3efc2`, CLI `57dc226`.
  사용자 원본·보존 요청한 외부 10개 프로젝트 폴더는 변경 대상이 아니다.
- 설치된 XG5000 실행 파일 버전은 4.82.1.0 (2026-07-20)이다.
- 제한된 일반 프로세스 조회에는 나타나지 않았지만, 추가 권한으로 조회한
  XG5000 PID 3132/12256/16752는 Session 1이며 응답 중인 창을 가진다.
  조회 권한의 차이를 앱 종료로 해석하면 안 된다.
- computer-use는 처음 창 목록을 일부 반환했으나 `launch_app` 두 번과 이후
  `list_windows`가 시간 초과됐다. 세션 초기화 뒤에도 조회가 실패했다.
  이후 새 프로세스를 추가로 실행하지 않았다. 이 도구의 연결 실패는 LD 불가능의 증거가 아니다.
- 기존 `live/xg5000_ladder.py:apply_ld_operand`를 읽었다. 기존 요소 하나의 값을
  대화상자로 치환하고 before/after payload를 비교한다. 접점·분기 생성 코드는 아니다.
- 설치 실행 파일의 embedded type library를 실제로 읽었다. `IApplication`에는
  `GetEditorObject(BSTR)`, `GetGridObject(BSTR)`, `GetGridObjectFromHandle(LONG)`가 있다.
  반환 인터페이스 `IEditorObject`/`IGridObject`에는 `Execute(BSTR) → BSTR`만 선언돼 있다.
  이는 편집 API 후보의 존재를 확인한 것이며 LD 변경 명령/인자나 호출 성공의 증거는 아니다.
- 이번 실행에서 작성·저장·재시험한 LD 결과물과 자연어 제품 Agent 실행 근거는 아직 없다.

재실행 가능한 설치 API 조회 코드는 CLI 저장소의
`scripts/Inspect-XG5000-EditorApi.ps1`이다. 실행 객체 생성이나 ROT 연결 없이
`LoadTypeLibEx(REGKIND_NONE)`로 파일의 타입 정보만 읽는다. 실행 결과는
XG5000 4.82.1.0, `IApplication` GUID `3350bb88-b01c-4ad3-94f1-97797b2dad5b`,
DISPID 23/24/25와 두 editor/grid 인터페이스의 DISPID 1 `Execute`였다.
이 코드는 조사 도구이며 목표인 LD 작성·변경 실행 코드를 대신하지 않는다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\controlstudio-xg5000-cli\scripts\Inspect-XG5000-EditorApi.ps1
```

명령은 workspace 루트 기준이며 실행 정책 옵션은 해당 프로세스에만 적용한다.
이번 실제 실행에서는 번들 PowerShell 7의 `pwsh.exe`로 같은 파일을 실행했다.

## 4. 실행 후보와 채택 조건

**설계 가정:** 장비별 정답을 코드화하지 않고, 모델이 LD 요소/연결과 필요한 작업을
결정하며 실행기는 일반 편집 동작을 제공하는 구조가 필요하다. 다음 중 실제로 작동하는
가장 단순한 경로를 채택한다. 아직 backend 선정 완료가 아니다.

- **설치된 편집 API:** vendor 타입 정보와 명령 계약을 읽는다. 직접 LD 구조를
  생성/삽입/삭제하고 결과를 읽는 호출이 확인되면 이를 먼저 실행한다.
  `Execute(string)`가 있다는 것만으로 LD 수정 API가 있다고 단정하지 않는다.
- **LD 편집기의 직접 조작:** 관측한 프로그램/셀에서 접점·분기·배선·명령·설명문을
  편집한다. 현재 창/모달 상태를 사용하며 이전 화면의 좌표를 반복 재생하지 않는다.
  반복적으로 확인된 일반 동작만 최소 코드로 묶는다.
- **파일 구조 직접 쓰기:** XG5000이 받아들이는 구조/저장 계약과 실제 열기·부분 변경
  근거가 확보될 때만 후보로 올린다. 미해석 binary를 추측 수정하거나 IL로 우회하지 않는다.

핵심 동작 하나의 통과 후 지원하는 변경과 아직 못하는 변경을 구분한다.
채택 경로의 기존 한-operand 계약·고정 compiler·잘못된 fallback과 소비자를 함께 교체한다.
새 helper를 추가하고 이전 결함 경로를 기본 실행으로 남기면 교체 완료가 아니다.

## 5. 완성품까지의 구현 순서

| 순서 | 구현할 실제 능력 | 다음 단계로 넘어갈 근거 |
| --- | --- | --- |
| 1 | LD 작성·구조적 부분 편집·읽기·검사·저장 | 격리된 XG5000 프로젝트에 실제 변경이 남고, 대상 밖 구조가 보존된다. 재실행 가능한 최소 실행 코드와 저장 결과가 있다. |
| 2 | 모델 주도 tool calling | 자연어 요청을 받은 모델이 필요한 조사와 LD 동작을 선택하고 실제 결과/오류로 다음 행동을 결정한다. 장비별 고정 생성/수리 순서가 없다. |
| 3 | 실제 웹과 대표 대동인덱스 작업 | 일반 사용자의 요청→조사/설계→실제 LD 제작·저장이 연결된다. UI의 완료 문구가 도구 결과와 일치한다. 필요한 I/O·운전 조건은 사용자 자료에서 확보하고 임의 예제로 낮추지 않는다. |
| 4 | 실패 관측→수정본 재시험 | XG-SIM 실패가 모델에 돌아가고 모델이 부분 수정한다. 적용·저장·readback한 수정본을 실행해 결과를 관측한다. 출력 강제 쓰기/이전 파일 재실행을 성공으로 세지 않는다. |
| 5 | 후속 변경·중단/재개·작은 문맥 | 요구·진행·현재 소스를 유지하면서 부분 조회하고 이어서 수정한다. 긴 로컬 추론을 획일적인 시간/회수 제한으로 중단시키지 않고 사용자의 취소는 별도로 처리한다. |
| 6 | 다른 장비와 LD 가독성 | 두 펌프 교번 운전에서 수위·고장 시 예비 펌프 전환을 같은 도구로 수행한다. 사람이 LD에서 의도를 읽고 후속 수정할 수 있다. |
| 7 | 최종 제품 배포 | 단일 설치/실행, provider 설정, 데이터 보존·업데이트를 실제 사용자 경로로 연결한다. 물리 PLC와 다른 벤더는 PRD의 별도 후속 범위를 유지한다. |

이번 작업에서 전부 재개발하지 않는다. 1의 타당성을 확보한 뒤 대표 사용자 요청 하나를
최소 형태로 끝까지 연결하고, 확보/실패한 근거로 나머지 구현 순서를 구체화한다.
1만 성공해도 2~7을 완료라고 표시하지 않으며, 요청 하나만 성공해도 일반화를 단정하지 않는다.

## 6. 작업 계약과 실행 기록

- 개발 작업자는 사용자 지정 `gpt-6.1-sol/high`로 사용한다. 이는 제품 내부 모델 설정과 다르다.
  파일 소유권을 나누고 같은 파일/실제 XG5000 창을 동시에 수정하지 않는다.
- 현재 문서 편집 소유자는 총괄이다. 작업자는 요구사항 및 설치 API를 읽기 전용으로 조사한다.
  실제 IDE 조작도 총괄 한 명만 맡는다.
- 제품 모델은 사용자가 선택한 GPT 6 luna/reasoning max 프로필을 실제 endpoint에서 확인해
  사용한다. 키는 문서·로그에 쓰지 않는다. provider 설정 확인이 LD 직접 편집 가능성 판정을 대신하지 않는다.
- 이번 작업에서는 테스트 코드·mock·framework를 만들지 않는다. 실제 동작을 가능하게 하는
  최소 실행 코드만 작성한다. 새 가설 없이 실패한 같은 동작을 계속 반복하지 않는다.
- 실행 기록은 이 문서의 현재 사실, 최소 코드, 격리된 한 작업 프로젝트에 연결한다.
  다운로드 폴더에 임시 프로젝트를 누적하지 않는다.

**바로 다음 실행:** 기존 XG5000 프로세스의 정상 편집 창에 연결하거나 확인된 vendor
LD API를 통해, 1절의 구조 생성/부분 편집을 수행한다. 현재 화면 제어 연결은 미확보다.
연결 부족을 LD의 기술적 불가능으로 바꾸거나 문서 완성으로 덮지 않는다.
