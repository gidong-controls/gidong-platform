# 09. 다음 구현 단계용 대체 Goal

**상태: 다음 구현용. 구조 결함 제거는 필수 범위로 확정했으며 이번 문서 보완에서 실행하지 않는다.** 다음 채팅에서 구현 요청을 받으면 사용한다. RB-01의 미결 제품 조건과 RB-02의 호출/상태 명세는 구체화하되, 확인된 결함을 제거할지 다시 결정하지 않는다.

## Goal — ControlStudio 오프라인 PLC Agent의 실제 수정·완성 흐름 복구

### 실행 조직 — 사용자 지정 Luna max

- 주 에이전트: 총괄 설계, 좁은 작업 분할, 계약 결정, 변경 통합, 독립 검토와 최종 사용자 흐름 인수 책임. 작업자의 완료 보고만으로 제품 완료를 선언하지 않는다.
- 구현 하위 에이전트: **`gpt-5.6-luna` / reasoning effort `max`**를 실제 생성 설정으로 명시한다. 이전 Sol medium 지정은 과거 기록으로만 남긴다. 지원되지 않으면 설정 실패를 알리고 사용자 동의 없이 다른 모델로 대체하지 않는다.
- 독립적으로 진행할 수 있는 bounded 작업만 위임한다. 각 작업에 Task/SC ID, 정확한 repo/파일 소유권, 목표·비범위·입출력 계약·완료/검증 조건을 제공한다. 같은 파일의 동시 쓰기는 금지한다.
- `collaboration.spawn_agent`가 제공되는 환경에서는 `model="gpt-5.6-luna"`, `reasoning_effort="max"`를 지정한다. 모델 override와 함께 `fork_turns="all"`을 쓰지 않고 `none` 또는 필요한 최근 turn 수와 명시적 작업 맥락을 전달한다. 실제 사용 도구의 지원 계약을 따른다.
- 이 설정은 Codex 개발 작업자용이다. 제품 내부의 모델 연결/`100.64.0.1` endpoint·credential은 임의로 바꾸지 않는다. 이번 핸드오프 갱신에서 작업자를 실제 생성하거나 전역 Codex 설정을 변경하지 않았다.

모델 ID와 max 지원은 [공식 OpenAI 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-luna)로 확인했다(2026-09-20). 실제 다음 세션의 모델 제공 여부는 해당 도구 결과로 확인한다.

### Outcome

합의된 Windows/LS XG5000/XG-SIM·모델 지원 프로필에서, 일반 사용자의 자연어 목표를 받은 ControlStudio가 기존 작업공간과 도구를 사용해 PLC 프로젝트를 조사·작성·실행·수정하고, 사람이 읽을 수 있는 native 작업본과 해당 revision의 검증 결과를 전달한다. Agent의 설계/도구/수정 판단을 기계별 정답 workflow로 대체하지 않는다.

완료할 사용자 여정은 다음 네 가지다.

1. **신규:** 대동인덱스 신규 요청으로 시작, 필요한 요구만 질문, 확정 조건 보존, 생성→native 적용→저장/재열기→합의 시나리오 완료.
2. **실패 후 수정:** 관측한 실패를 Agent가 조회·일반 편집으로 해결, 변경 source를 실제 적용·저장·readback, **그 source**로 재시험. 기존 성공 receipt의 재사용으로 통과 금지.
3. **후속/복구:** 기존 프로젝트 설명과 자연어 변경, 중단·재시작·후속 지시 처리. 원본 보존, 결과불명 중복 실행 없음, 요구/작업 내역 유지.
4. **일반화:** 제어 구조가 다른 합의 장비 사례 하나에서 동일 일반 도구 루프 사용. 인덱스 전용 수리 코드에 의존하지 않음.

### Constraints

### Verification

1. **계약/회귀:** RB-04/05의 실제 pytest 수집·실행 및 의도한 실패 탐지. planning valid 이후에도 조회/편집/실행 선택 가능, compiler legality와 정책 분리, goal/receipt 결속, interruption/idempotency를 검증한다. mock은 이 층에서만 증거다.
2. **실제 수정:** baseline과 변경된 source hash, working-copy identity, candidate/attempt/receipt, native 저장·readback·재열기, 각 시험 결과를 연결한다. readback이 이전 source면 실패다.
3. **동작 oracle:** RB-01 확정 요구와 AF-04 반례를 포함한 입력/상태 전이 표를 시험한다. 성공/실패 판정을 모델의 자기 평가만으로 결정하지 않는다.
4. **제품 사용성:** 일반적인 첫 요청에서 시작해 내부 정책 문구/ID 수동 입력 없이 끝낸다. 사람이 native를 다시 열어 심볼/주석/주소 타입/출력 의미를 검토한다. Agent의 작업 대신 개발자가 수동 수리한 경우 별도 개입으로 기록한다.
5. **일반화·복구:** 다른 장비 사례, 기존 프로젝트 질문, 후속 수정, 사용자 중단/재시작, 범위 밖 동작 거부를 확인한다.
6. **provider/문맥·비밀:** 합의된 지원 endpoint 도구 왕복과 실제 장문 경계, 근거 정보 보존/compact 후 재조회, credential가 DB/API/log/export에서 평문으로 남지 않는 합격 절차를 수행한다.
7. **보고:** 재현 명령/환경/버전·일시·결과 artifact·실패 포함 전체 manifest를 남긴다. CI 통과와 native 합격과 제품 인수는 각각 표시한다.
8. **구조 제거:** SC별 기존 진입점/호출자/flag/fallback/test 기대값과 대체 경로를 대조한다. 결함 동작이 사라진 negative 회귀와 새 경로의 positive 회귀를 모두 통과해야 한다. 실기 연결 항목은 실제 수정 source receipt가 추가로 필요하다. 새 경로가 성공해도 옛 결함 경로가 신규 실행에서 도달 가능하면 실패다.

**종료 판정:** SC-01~06 제거·교체와 네 여정, 필수 P0/P1 조건에 미해결 실패가 없고, 합의된 인수자가 확인한 경우에만 complete로 표시한다. 구조 항목을 검증하지 못했으면 미완료/blocked이지 “개선 권고로 남긴 완료”가 아니다. 문서/PR/컴파일 완료로 대체하거나 production 배포 완료를 함께 주장하지 않는다.

### 명시적 비범위

물리 PLC 운전/쓰기, SSH·Session0·Task Scheduler 해결, 모든 vendor/모든 명령, 모든 OpenAI-compatible 모델의 동등 품질, 전면 CLI backend 추출, production 서명·설치 출시는 이 Goal의 자동 범위가 아니다. RB-20~24는 별도 결정/출시/선택 작업이며, 현 기능 인수의 미완료를 숨길 핑계로 사용하지 않는다.

### 중단·에스컬레이션 조건

- 동일 가설/동일 명령이 새 정보 없이 두 번 실패: 세 번째 반복 금지. 실패 source/로그/가설/다음 검증을 기록하고 제한된 다른 접근으로 전환한다.
- 필요한 사용자 결정·권한·모델 capacity·native 환경이 없음: 해당 작업을 blocked로 표시하고 독립 작업만 계속한다. 영구 대기나 승인 우회 금지.
- 외부 native 변경/결과불명/원본 위험: mutation 중단, 근거 보존, 조회·사용자 선택으로 복구한다.
- 성능 예산 소진: timeout/토큰을 계속 늘리지 말고 구간별 원인과 남은 작업을 보고한다. 예산 소진은 성공이 아니다.
- 범위를 바꿔야만 합격 가능: 요구를 몰래 낮추지 말고 D-01 변경 결정을 요청한다. 같은 사유가 반복되면 재계획하고 해당 Goal을 미완료로 보고한다.

작업 종료 후 합격/실패·변경 소스·검증 범위·남은 blocker·다음 작업만 짧게 핸드오프에 갱신한다. 새 진단 문서만 계속 추가하지 않는다.
