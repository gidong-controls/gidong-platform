# 01. 제품 목적 재구성

감사일: 2026-09-20. **현재 제품의 설명과 다음 구현의 권고안을 구분한다.** 이 문서는 PRD 변경 승인이 아니다. 근거 ID는 [색인](10_EVIDENCE_INDEX.md), 충돌은 [요구사항 감사](02_REQUIREMENTS_AUDIT.md)에 연결된다.

## 1. 한 문장 정의

ControlStudio는 **PLC 엔지니어가 자연어로 설계·이해·변경을 요청하면, 모델이 프로젝트 작업물을 읽고 편집하고 실제 엔지니어링 도구의 결과를 관찰하며 수정하여, 사람이 이해하고 다시 열 수 있는 PLC 프로젝트를 완성하는 데 협업하는 데스크톱 에이전트**다.

근거: PRD:12,64,94,179 및 사용자의 “PLC 에이전트, 룰베이스 프로그램이 아니다” 지시(E02,E15). 확인됨·높음. 단순 JSON 생성기, 검증 대시보드, 고정 시나리오 실행기는 제품 정의가 아니다.

## 2. 대상 사용자와 문제

| 대상 | 해결하려는 문제 | 핵심 가치 |
|---|---|---|
| 제어 설계 엔지니어 / SI | 요구를 실제 PLC 코드·설정·시험으로 연결하는 반복 작업 | 문맥을 유지하는 작성·시험·수정 협업 |
| 유지보수 엔지니어 | 기존 설비 코드의 원인·영향 파악과 안전한 변경 | 근거 있는 설명, 작업본 변경, 재확인 |
| 검토자 / 인수 담당자 | 생성 산출물이 무엇이며 무엇을 시험했는지 판단하기 어려움 | 읽을 수 있는 래더·심볼·변경 설명과 추적 가능한 시험 |
| 배포·운영 담당자 | 내부 개발 저장소에 의존하는 설치·업데이트 | 검증된 구성의 배포물과 사용자 데이터 보존 |

PRD:94 이하(E02). 첫 MVP의 주 사용자는 PLC 엔지니어다. PLC 지식이 없는 사용자가 검토 없이 실제 설비를 운전하게 만드는 제품으로 재해석하지 않는다.

## 3. 핵심 사용자 작업과 흐름

1. 프로젝트를 선택하거나 “대동인덱스 같은 장비를 만들어 줘”처럼 목표를 말한다.
2. 에이전트는 기존 프로젝트·확정 요구사항·가능한 도구를 읽는다. 기능·I/O·운전 의미가 불명확하면 필요한 질문만 한다. UUID, 원본 보호, 물리 쓰기 금지를 사용자가 매번 입력하지 않아도 작업 정책이 적용된다.
3. 요구사항과 작업물을 유지하며 설계·심볼·래더를 작성/편집한다. 하나의 큰 응답이나 고정 생성 단계가 성공해야만 진행되는 방식에 의존하지 않는다.
4. 요청에 필요한 검사·XG5000 적용·저장·재열기·XG-SIM을 선택해 실행한다. 오류는 모델이 조사하고 해당 작업물을 수정한다.
5. 수정한 **그 소스**가 저장·readback·시험된 것을 확인한다. 같은 사용자 작업은 유지하되 실행 시도와 증거는 revision별로 분리한다.
6. 결과물 위치, 변경 내용, 검증 범위, 미해결 사항을 사람이 읽는 말로 전달한다. 사용자가 후속 변경·중단·재개를 요청할 수 있다.

이것은 권고 목표 흐름이며 현재 전 구간이 통과했다는 뜻이 아니다. planning의 제어 단절과 수정본 적용 경계는 AF-01/03이다. 단순 설명 요청에 저장·SIM을 강제하지 않는다(EXE-05).

## 4. 반드시 필요한 기능 / 있으면 좋은 기능

**필수:** 대화·요구사항 지속, 기존 프로젝트 근거 조회, 부분 편집, 모델 주도 도구 선택, 정확한 tool 결과, 오프라인 작업본, 변경 전 기준점과 원본 보호, 실제 적용/저장/readback, 요청에 맞는 시험과 수정 루프, 중단/재개, 사람이 읽을 수 있는 native 산출물, 완료 범위의 정직한 표시. 커넥터와 장문 지원은 명시된 지원 프로필에서 검증한다(E02,E04~E13).

**후순위:** 추가 PLC vendor, 물리 설비 운전, 별도 협업/분산 서버, 다중 에이전트 자동 조직, 고급 대시보드, 광범위 텔레메트리. 후순위 여부는 제품 가치보다 낮다는 뜻이 아니라 현재 오프라인 복구의 선행 조건이 아니라는 뜻이다.

## 5. MVP 경계

권고하는 복구 MVP는 **한 Windows 대화형 환경의 LS XG5000/XG-SIM 오프라인 PLC 작업**이다. 기존의 생성·설명·변경 경로를 함께 유지한다. 다음 네 여정이 고정 인수 corpus다.

- 신규: 일반적인 자연어 요청과 필요한 질의응답으로 대동인덱스 작업본 생성 → native 적용 → 저장/재열기 → 합의한 시험.
- 수정: 시험에서 드러난 실패를 일반 도구로 조사·수정 → 새 소스 적용 → 새 증거로 재시험. 기존 성공 결과를 재사용해 성공으로 표시하지 않음.
- 후속/복구: 생성 프로젝트에 자연어 변경, 중단/재시작 후 확정 요구·완료 작업을 유지. 원본이나 실제 PLC에 쓰지 않음.
- 일반화: 인덱스와 제어 구조가 다른 오프라인 장비 한 사례에도 같은 도구 루프 사용. 장비별 정답 수리 분기 추가 없이 수행.

정확한 장비 요구, CPU/명령 지원 집합, 모델/서버 버전, 반복 횟수와 시간 예산은 **RB-01에서 고정**한다. 이 질문을 매 구현 단계에서 다시 열지 않는다. 전체 기능을 폐기하고 “인덱스 템플릿”만 만드는 축소는 권고하지 않는다. 생산용 설치/서명 합격과 이 개발 MVP 합격은 별개다(PRD:459,510).

## 6. 명시적 비범위

- 이번 감사: 프로덕션 수정, 앱·모델·실기 재실행, DB 변경, 설치·배포·삭제, 이슈 생성, 구현 시작.
- 다음 오프라인 MVP: 물리 PLC 쓰기/운전, SSH/원격 GUI 해결, 모든 제조사/모든 명령 지원, 모든 모델의 동일 품질 보장, 무인 안전 인증, production 서명 완료를 암묵적으로 포함하지 않음.
- 200k 문맥 요구는 비범위로 버리지 않는다. 정확한 단위·사용 프로필을 결정하고 실제 시험할 별도 필수 작업으로 남긴다. 8k 제한으로 대체하지 않는다.

## 7. 데이터·개인정보 경계

프로젝트 원본/작업본, 설비 로직·I/O·운전 요구, 대화, 도구 결과, native receipt, DB에 저장된 이력은 사용자 데이터다. 모델 endpoint가 외부면 전송 범위를 알려 동의를 받아야 한다. 자격증명과 사용자 지정 header는 프로젝트 산출물·로그·공개 저장소에 노출되면 안 된다. 모델은 DB/MCP에 직접 권한을 갖지 않고 Host를 통해 요청한다(E03,E10,E11).

현재 key/header 평문 SQLite 저장은 확인됨(AF-08); 실제 유출은 확인되지 않았다. 보존 기간·삭제/내보내기·백업·텔레메트리 정책은 미결(AF-12). 요구만 있는 정책을 구현 완료로 표시하지 않는다.

## 8. 외부 시스템·운영 환경

| 의존성 | 역할 / 경계 | 감사 판단 |
|---|---|---|
| Windows 대화형 로그인 세션 | XG5000/XG-SIM 자동화 실행 | 기존 실기 성공 기록 있음; 현재 화면 인수는 접근 불가(E08,E20) |
| LS XG5000 / XG-SIM | native 프로젝트와 오프라인 시험의 실제 의미 | 버전/CPU/명령 지원 프로필 고정 필요 |
| OpenAI-compatible 모델 endpoint | 모델 추론과 도구 선택 | API 호환과 설계 능력은 별개; 사용자 endpoint `100.64.0.1`의 현재 가용성은 미시험 |
| Host SQLite / 작업 파일 | authoritative 이력·작업 상태·증거 | 기존 store/transaction/lease 보존; 실제 복구 인수 부족 |
| Platform / Agent / MCP / CLI artifact | UI·정책·추론·실행 조합 | 독립 Git 저장소 4개, 버전/BOM 경계 유지 |
| GitHub·CI·서명 주체 | 변경 검토·출시 | 원격 상태 접근 불가; 출시에 필요한 별도 blocker |

현재 설치 런타임 차이는 E17에 기록했다. 혼재가 곧 장애 원인이라는 증거는 없다. 제품 검증 환경을 선언하고 재현해야 한다.

## 9. 성공 지표와 완료 판정

| 지표 | 측정 방식 | 합격 기준의 상태 |
|---|---|---|
| 사용자 목표 달성 | 고정 네 여정 각각의 요구–작업물–실행 증거 대조 | 제안: 모든 필수 여정 통과, 숨은 수동 코드 수리 없음 |
| PLC 동작 정확성 | 시작/정지/모드/상충입력/타이머/알람/복구 등 합의 시나리오, source hash 결속 | 알려진 AF-04 반례가 기대한 안전 동작을 만족해야 함 |
| 수정 루프의 실재 | 실패 소스와 수정 소스 및 각 native receipt/시험 결과 비교 | 새 소스 적용·시험을 증명, 이전 증거로 대체 0건 |
| 산출물 사용성 | native 재열기 후 심볼·주석·주소 타입·설명으로 엔지니어 검토 | 빈 심볼 표나 의미 불명 명칭에 의존하지 않음; 담당자 확인 |
| 무단 영향 / 허위 성공 | 원본/물리 쓰기, 증거 불일치, 중단 뒤 이중 실행 관찰 | 0건(PRD 안전 불변조건 유지) |
| 시간·재시도·토큰 | 모델 호출/도구/대기별 시간, 사용자 개입 횟수 | 기존 PRD 수치 미결; RB-01에서 예산 확정, 미확정은 통과 아님 |
| provider·장문 | 지원 endpoint별 도구 왕복·중단·재개; 합의한 200k 경계에서 정보 보존 | 모델/서버 실제 용량 내 측정; 상수만으로 통과 처리 금지 |

한 번의 SIM 성공, test count, JSON schema-valid, build exit0, 문서 완료는 위 제품 인수의 대체물이 아니다. [대체 Goal](09_REPLACEMENT_GOAL.md)이 구현 단계의 종료·중단 조건을 정의한다.
