# 00. ControlStudio 제품 복구 감사 — 최종 요약

기록 상태: 2026-09-20 감사. 현행 개발은 [PRD](../../PRD.md)와
[구현 계획 §4·§5](../AGENT_PRODUCT_PLAN.md)를 따른다. 아래 상태·RB 목록은 당시
기록이며 현재 실행 순서가 아니다. 결함 경로의 제거·교체라는 사용자 요구는 유지하고,
실제 남은 활성 호출자와 대체 동작을 현행 계획에서 구현한다.

감사 기준일: **2026-09-20**. 범위: 현재 소스·PRD·기존 감사/실행 이력·Git 포렌식·공식 비교 자료를 읽고 복구 문서/백로그를 작성. **감사 완료와 제품 완료는 다르다. 현재 제품은 합격 상태가 아니다. 이번에 제품 코드·DB·실기 결과를 변경하지 않았다.**

## 한 문장 제품 정의

**PLC 엔지니어가 자연어로 요구를 말하면, 모델이 지속되는 프로젝트 작업물을 조사·작성·실행·수정하고, 사람이 읽고 다시 열 수 있는 PLC 프로젝트와 실제 검증 결과를 제공하는 데스크톱 PLC 에이전트다.** 검증 목록 UI나 인덱스 전용 룰베이스 생성기가 아니다(PRD:12,64,179; E02/E15).

## 최종 판정과 중요한 정체 원인

**후속 사용자 지시 반영:** [SC-01~06 필수 제거·교체](07_RECOVERY_DECISION.md#필수-제거교체-목록)를 확정했다. 확인된 결함은 검토 대상으로만 남기지 않는다. 각 항목의 옛 결함 경로 제거와 대체 동작을 입증해야 하며, 새 경로만 추가하거나 예전 fallback을 남기면 미완료다. 기존 기반 보존은 사용자 데이터와 유효한 계약의 보존이지 결함 구현까지 유지한다는 뜻이 아니다. 실제 코드 삭제/수정은 이번에 하지 않았다.

영향도 순 상위 다섯 원인:

1. **신규 설계가 일반 도구 루프에서 분리되어 valid 뒤 publish를 강제**한다. 수정·실행 선택이 목표까지 이어지지 않는다(AF-01; E04, 확인됨·높음).
2. **compiler의 합법성 검사와 특정 장비 설계 정책이 결합**되어 일반적인 모델 설계/수정을 제약한다(AF-02; E05, 확인됨·높음).
3. **수정 source·native 실행·요구별 합격·전체 완료가 일관되게 연결되지 않았다.** 기존 resume은 같은 build용이며, 이전 8개 시험은 최종 반례를 포괄하지 않는다(AF-03/04/06; E06~E08, 계약/반례 확인·통합 미입증).
4. **국소 오류 수리와 재시험을 반복하며 사용자 결과보다 내부 경로 복구에 집중한 전략**이 남은 구조 문제를 반복 노출했다(AF-10; E14/E15/E21, 높은 가능성). 전체 소요 시간/비용과 과거 모든 시도는 복원하지 못했다.
5. **행동 CI·제품 oracle와 문서/테스트 기대값 정합성이 부족**하다. 테스트는 있지만 CI가 실행하지 않고, 일부 기대값은 publish-only를 고정한다(AF-07/10; E04/E09, 확인됨·높음).

과거 XG5000 생성·저장·재열기와 XG-SIM 8개 성공은 유효한 성과다. 다만 수동 모드/정지 해제의 정적 반례와 native 심볼 표 부재가 남아 전체 인수 근거가 아니다(E08). “실제로는 다 됐는데 확인만 못함”으로 판정하지 않는다.

## 자료와 제한

- 현재 코드·Git·설정·테스트 본문을 읽고 기존 09-19/20 보고서를 대조했다. 읽기 전용 Sol medium 작업자 세 명의 제품/구조·품질/포렌식 결과를 주 감사자가 조정했다. 외부 인간 전문가 인증은 아니다.
- 비교 대상은 PLC3개+인접 Agent2개, 기술 자료2개, 공개 구현1개로 한정했다. [06](06_BENCHMARK_ANALYSIS.md). 공식 OpenAI 문서는 Codex/AGENTS 설정 규칙을 확인하는 데 사용했으며 ControlStudio 내부 설계의 증거로 대체하지 않았다.
- 새 모델/XG5000/XG-SIM/테스트 suite 실행은 하지 않았다. 현재 UI 화면은 접근 불가. 원격 PR·이슈·CI·서명 출시와 과거 전체 세션/정확한 formal Goal은 미확인(E15~E20).
- 보안 추가 발견: API key/header가 SQLite에 평문 저장됨(AF-08). 실제 유출·credential 내용은 조사하지 않았으며 기능 정체의 주원인으로 잘못 분류하지 않았다.
- 사용자 표현 “2주 이상”과 별도로 Git에는 08-15~09-20, 집중 작업 08-31~09-20 기록이 있다. 이를 정확히 동일 formal Goal의 연속 실행 기간이라고 단정하지 않는다.
