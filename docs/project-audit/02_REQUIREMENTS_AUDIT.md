# 02. 요구사항 감사

2026-09-20. 근거는 [E02/E15/E21](10_EVIDENCE_INDEX.md). **PRD에는 이미 제품 정의·27개 요구사항·완료 기준이 있다.** 문제를 “PRD가 전혀 없다”로 진단하지 않는다. 아래는 추적 가능한 감사 해석이며 PRD 자체를 수정하지 않았다.

## 출처의 우선순위

1. 현재 사용자의 감사 전용 범위가 이번 행동 권한을 정한다.
2. 사용자에게 확인된 제품 의도와 PRD의 명시적 요구가 제품 기준이다. 서로 충돌하면 결정 항목으로 남긴다.
3. 승인된 설계/계약은 구현 제약을 설명한다. 9월 19~20일 설계 제안은 자동으로 승인된 결정이 아니다.
4. 소스·데이터·실행 증거는 현재 실제 상태를 보여 준다. 테스트의 기대값이 제품 요구보다 우선하지 않는다.
5. README/핸드오프/과거 세션은 맥락이다. 오래된 “완료” 문장은 현재 인수를 대신하지 않는다.

## 요구사항 매트릭스

두 표는 **같은 ID로 결합되는 하나의 요구사항 기록**이다. 표 A는 출처/해석/가치/필수·범위/구현 상태/분류, 표 B는 의존/실현성/모호성·충돌/검증·완료/권장 조치를 담는다. PRD 원문 위치: `PRD.md:200~245`(E02). 원문은 긴 인용 대신 요구의 핵심을 요약했다. 상태는 이번 읽기 기준이며 “존재”는 실제 인수 통과를 뜻하지 않는다.

모호 표현을 삭제해서 목표를 약화시키지 않는다. “완벽하게”는 지정된 여정·불변조건·품질 oracle로 바꾸고, “전부”는 명시된 지원 집합으로 바꾼다. 역할이 많다는 이유로 LLM의 설계/래더 작성 책임을 없애지 않는다. **삭제 권장:** 사용자 가치 없는 장비별 정답 수리 강제와 발행=목표완료 등 구현 가정. 요구 자체의 폐기는 사용자 결정 없이 수행하지 않는다.

## 누락과 미확인

- 기존 formal Goal 원문/기간 전체 세션, 원격 이슈/PR/CI가 완전히 확보되지 않았다(E15/16). 제품 요구가 이 파일로 전부 승인되었다고 주장하지 않는다.
- 성능 예산, 재시도/질문 허용 기준, 담당 인수자, 정확한 CPU/명령·provider·200k 지원 프로필이 미결이다(RB-01).
- 자격증명 저장, 데이터 보존/복구, release 서명·저작 주체의 정책 결정이 필요하다(RB-19/20/22). 이번에 비밀 값은 조회하지 않았다.
- 실현 불가능하다는 전체 판정은 아니다. 현재 planning/적용 경로 그대로로는 핵심 요구 충족을 입증할 수 없어 **모듈 재설계가 선행**되어야 한다.
